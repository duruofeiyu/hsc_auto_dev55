# Bug 标题：主机管理"全选当页"删除后，二次全选计数错误且删除成功提示与实际未删数据不一致

- **环境 / 版本**：HSC 测试环境 55（192.168.124.55:26400）/ 主机管理页面 / Web 浏览器
- **严重级别**：严重
- **优先级**：P1
- **模块 / 页面**：主机管理 > 全部主机列表
- **报告人 / 日期**：（请填写）
- **指派给**：（请填写）

## 前置条件
- 已登录 HSC 系统，并进入"主机管理"模块。
- 主机总数量大于一页，当前列表存在分页（示例：共 845 条，30 条/页）。

## 复现步骤
1. 进入"主机管理"页面，保持默认"全部主机"列表。
2. 点击表头"全选"按钮，勾选当前页全部记录（页面顶部显示"已选择 30 项"）。
3. 点击"删除"按钮，确认删除。
4. 观察列表：当前页 30 条记录被删除，总条数从 875 减少（示例减少为 845 条），第一次删除实际生效。
5. 不刷新页面、不切换分页，再次点击表头"全选"按钮。
6. 观察页面顶部选中提示：显示"已选择 60 项"。
7. 再次点击"删除"按钮，等待前端响应。
8. 观察列表数据：记录数与第一次删除后保持一致，未继续减少。

## 预期结果
1. 第一次删除成功后，列表刷新，当前页实际剩余记录数应正确显示。
2. 再次点击"全选"时，应基于**当前页最新数据**计算并选中，提示数量应与当前页实际记录数一致（示例中应远小于 60 项）。
3. 再次点击"删除"后：
   - 若确实有选中记录，应真实删除并刷新列表；
   - 若选中逻辑异常/无有效记录，应给出明确错误提示，而不是提示"删除成功"。

## 实际结果
1. 第一次删除成功，当前页 30 条记录被真实删除，列表刷新。
2. 第二次点击"全选"后，页面顶部提示"已选择 60 项"，明显超过当前页实际可勾选数量。
3. 再次点击"删除"，前端弹出"删除成功"提示。
4. 但列表数据未减少，仍显示第一次删除后的记录数量与内容，第二次删除未实际生效。

## 复现概率
必现

## 备注
- 该问题疑似前端在首次删除后未重置全选状态 / 未基于最新分页数据重新计算选中数量，导致第二次全选时仍保留旧的分页缓存数据或重复累加选中计数。
- 第二次删除时可能提交了无效/已删除的 ID 列表，后端未校验直接返回成功，或前端未真实调用删除接口但显示了成功提示。
- 建议排查：
  1. 首次删除后 `selectedRows` / 分页 `pagination` 状态是否正确清空；
  2. "全选当页"逻辑是否依据当前页 `currentPageData` 重新计算；
  3. 第二次删除请求的 Network 请求参数（ID 列表）是否为空或包含已删除 ID；
  4. 后端删除接口对空 ID 列表或不存在 ID 的返回码与提示文案。
