## [资产探测任务配置 versionIntensity 传入非法值返回成功但参数未生效（静默丢参）]

- **环境 / 版本**：HSC 55 开发环境（192.168.124.55:26400）/ V1.4.0 / 账号 chenyh
- **严重级别**：一般
- **优先级**：P2
- **模块 / 页面**：新安服流程管理模块 - 资产探测任务（asset/probe）配置
- **报告人 / 日期**：陈宇航 / 2026-08-31
- **指派给**：（待指派，后端开发）

### 前置条件
1. 已登录 HSC 55 环境，具备资产探测任务编辑权限（chenyh 账号）
2. 存在一个可编辑的资产探测任务（验证脚本使用 taskId=2092539667005071362）
3. 该任务当前 versionIntensity 有已知可生效的合法值（验证中仅值 4 生效）

### 复现步骤
1. 进入 HSC 新安服流程管理模块，打开资产探测任务（asset/probe）编辑页
2. 修改 `versionIntensity` 字段为非法值（如 999、0、1、5 等；合法范围疑似仅 4）
3. 点击保存，调用 `PUT /hsc-system-api/asset/probe/{taskId}`
4. 观察接口返回：HTTP 200 且业务 `success=true`（看似保存成功）
5. 重新调用 `GET /hsc-system-api/asset/probe/{taskId}/execution` 查询任务详情
6. 解析响应体 `result.paramSnapshot.config.versionIntensity`，与第 2 步传入值对比

### 预期结果
- 传入非法 `versionIntensity` 时，接口应**明确拒绝并报错**（如参数校验失败、HTTP 400 或业务 code 错误），提示用户参数不合法；或按业务规则拒绝保存，不应静默接受。

### 实际结果
- 接口返回 HTTP 200 + `success=true`（前端/调用方判定为保存成功），但 `GET` 查回的 `versionIntensity` 仍为修改前的原值，传入的非法值**被静默丢弃**，用户全程无感知、无报错提示。
- 验证脚本对取值 `[0, 1, 4, 5, 999]` 实测：仅 `4` 生效，其余均"PUT 返回成功但查回不变"（静默）。

### 复现概率
必现（10 / 10 次；脚本自动化验证，除合法值 4 外全部静默）

### 备注
- 该缺陷为典型的「静默失败（silent failure）」：接口成功响应掩盖了参数未生效，比显式报错更隐蔽，易导致探测任务实际强度与用户配置不符。
- 仅 chenyh 账号验证；合法值 4 可正常生效，存在明确 workaround（仅使用值 4）。
- 验证脚本为临时探查脚本，按用户约定验证后由本人清理，不纳入框架仓库。

### 排查方向（根因提示，非定论）
后端可能**未对 `versionIntensity` 做取值范围校验**，或接受任意入参后在处理非法值时用默认值/旧值覆盖且不返回错误，导致静默丢参。建议：补充入参合法性校验，非法值明确报错而非静默接受。
